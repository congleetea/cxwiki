## 按任务类型选择工作方式

下面的 ingest、absorb 等词只是工作类型标签，不是需要在终端执行的命令；仓库没有实现斜杠命令解析器。

- **ingest / 收集**：读取官方来源；必要时保存 PDF 或关键代码；在 `raw/entries/` 记录标题、URL、获取日期、版本及关键章节/文件定位。下载失败明确记录，不假装读过。
- **absorb / 吸收 / 综述**：检索已有主题，核验旧结论；按具体问题综合，而非依次罗列论文摘要。已有文章先读再改，记录重要结论的变化。
- **migrate / 迁移**：只迁移本次指定主题。旧文引用回到论文/官方代码核验；图片和链接一并检查。不要批量复制旧文或把未迁移页面伪装成新库内链。
- **query / 查询**：区分库内事实与本次推理。普通问答不自动写入文件；用户要求沉淀时才更新文章。
- **lint / 检查**：先运行现有检查脚本，再核对结论与证据、公式与图。结构检查不能证明技术事实正确。
- **status / graph**：基于实际文件报告状态；关系图只表达有解释价值的关系，不追求全连线。

这些是自然语言工作模式，并非承诺环境中存在 `/wiki` 斜杠命令或自动化接口。

## 文件命名与系列归档

同一研究系列使用稳定、可排序的 ASCII 文件名，并共享系列前缀：例如 `pi-0-flow-vla.md`、`pi-fast-action-tokenization.md`、`pi-05-open-world.md`、`pi-series-overview.md`。用两位数字表达版本（`pi-05`、`pi-06`、`pi-07`），方法支线仍使用 `pi-` 前缀（`pi-rtc-real-time-chunking.md`、`pi-mem-memory.md`）。中文标题放在 frontmatter 的 `title` 和一级标题中；路径避免 π、冒号、空格和未编码的特殊字符，以便 Markdown 链接、脚本和不同文件系统稳定工作。重命名必须同步修正全库真实链接，并运行链接检查。

## 写作标准

首段给出问题、困难和文章核心判断；随后围绕读者真正需要理解的问题展开。不要机械填满固定章节，不用“提出了框架、显著提升”等摘要句替代方法解释。

**概念文章与综述承担不同职责，不能互相替代。**

- `00-concepts/` 的概念文章必须能独立、详细、由浅入深地讲透一个对象：从具体例子和问题开始，说明输入/输出、坐标或表示、直觉、必要公式、逐步流程、真实实现、设计理由、限制和来源。每个关键公式解释符号、维度、约定与假设；每个流程让读者能据此重建算法。图片应展开数据流、变量、坐标、模块或局部机制，而不是只作装饰。概念文章可以引用综述，但不能要求读者先读综述。
- `01-comprehensive/` 的综述只负责跨对象组织知识：时间线、方法关系、问题分解、特点、优缺点、差异、组合方式和阅读路径。它不重复单篇论文的完整推导、训练配方或逐层实现；需要细节时链接对应概念文章。不要把模型、数据集、控制器和训练算法放在同一张性能排名表中。
- 先判断材料应落在哪一层；同一事实在综述中用一句判断，在概念文中用证据、解释和公式展开。

解释算法时，让读者能重建它：输入是什么，在哪个坐标系、用什么单位和表示；经过哪些变换；求解哪些变量；目标和约束分别解决什么；输出交给谁。对每个必要公式解释符号与维度、假设和设计理由。给一个小例子，使关键步骤可检查。

明确区分：原文事实、作者报告的结果、代码中观察到的行为、本文统一推导、推断和未解问题。解释用的通用公式不是实现公式；符号或残差重写后说明约定。不要把库、算法、系统、控制器和数据集放在同一性能排名里。

关键事实与数字就近链接原始来源，优先论文具体章节、官方文档或固定 commit 的实现。性能数字保留硬件、数据、约束、批大小、精度、计时边界与是否复测；在线延迟不与离线批吞吐直接相比。跨论文消融不能替代同条件对照。

推荐 frontmatter：`title`、稳定 `id`、`type`、`created`、`last_updated`、`stage`、`verified_date`、`institution`、`tags`。`institution` 写论文或项目的主体机构；合作工作用多个机构连接，综述文章明确写“综述”或“多机构”，不要把引用对象误当作者机构。成熟度用 `seedling / budding / evergreen`；来源核验不等于实验复现，也不自动意味着 evergreen。

## 图示：用户明确的偏好

**不使用 Excalidraw，也不沿用手绘涂鸦风。** 参考用户喜欢的 PI-MEM 技术信息图形式：醒目深蓝标题、编号分区、蓝/紫/绿等语义配色，问题与方法并排，步骤用箭头串联，关键细节有局部展开。

以帮助理解为目的：总览图讲全貌，局部图讲坐标、变量、数据流、求解步骤或机制。不要把整篇文章缩成一张小字海报。使用可编辑 SVG，导出高清 PNG 嵌入 Markdown；本库图稿脚本可作样式参考，布局可按内容改变。精确公式、标签、箭头优先用矢量工具，避免生成式图片造成符号错误；真实场景插画确有帮助时再用图像生成。

图需有语义明确的颜色、清楚的箭头方向、足够留白、普通阅读宽度可读的字号。图注写明用途和来源，原创示意图不得伪装成论文实验图。必须实际渲染并查看成图，核对文字溢出、遮挡、公式和正文一致性。
